# 0009 - HTTP Mock 服务虚拟化:独立进程实例 + 声明式生命周期

日期:2026-09-08 · 状态:accepted

> **2026-09-11 注记:** 匹配顺序与未命中语义已被 [ADR-0011](0011-mock-rule-groups-passthrough.md) 修订
> (实例内全局扁平序→组间/组内两级序;未命中直接兜底→可选透传上游)。本篇其余决策(独立进程/声明式
> 生命周期/热更新)仍然有效。

平台新增「接口Mock」域(HTTP Mock 子域,企业级 mock server 路线):项目下可建多个 **Mock 服务实例**,
每实例=一个独立 Python 子进程(同 venv,`python -m` 拉起 uvicorn 小应用)+ 一个独立端口。端口留空则从
`mock_port_range`(默认 9001-9499)自动分配,可手填覆盖;保存前做冲突预检,停止态才可改端口。
生命周期为**声明式**:库中存 desired(running/stopped),平台后端重启自动拉起 desired=running 的实例,
拉不起来→错误态留消息;孤儿进程双保险(mock 子进程健康端点带实例令牌供启动对账识别 + 子进程监视父进程
父死自退);运行中每 ~10s 探活,子进程死亡→错误态手动重启。规则热更新走**子进程每请求实时读库**,
改规则下一请求即生效,零缓存失效逻辑。导航上「接口Mock」为项目态一级菜单组、子项「HTTP Mock」
(路由 `/projects/:id/mock/http`)——分组轴在 ADR-0007 的「AI 是否参与」之外新增**资源类型轴**,本 ADR
扩展之,不改写 0007。管理面权限沿用项目角色(viewer 读 / editor 及以上写,含启停与清空);服务面
mock 端口**无鉴权**(健康端点令牌仅用于孤儿识别,不做访问控制),内网边界同计划 9 SSE 先例。

## Considered Options

- 主服务 8000 端口挂 catch-all(`/mock/{pid}/{path}`)——拒:无鉴权流量混入管理端口,URL 带 API 前缀味,将来拆分更痛。
- 每项目固定单实例——拒:被测系统多下游服务时全挤一个端口靠路径区分,真实感打折;单→多迁移代价大于直接多实例建模。
- 每项目独立进程由 UI 完全启停、平台不管对账——拒:期望状态与实际状态分家(库说 running 进程已死)是进程管理烂尾首因,声明式对账是最低配闭环。
- 端口纯手填(启动才发现撞)或纯自动分配(无法对齐真实拓扑)——取混合+保存前冲突预检,把失败提前到保存时。
- 规则缓存+失效推送——拒:每请求读库毫秒级(测试替身非生产网关),正确性压倒性能,零失效 bug 面。
- 路径正则匹配——拒:与模板并存时命中预测性最差;模板+条件行已覆盖按 id 过滤场景。
- 脚本化响应/场景序列/HTTPS/随机延迟/连接重置/非 JSON 体匹配——一期 DEFER;
  **代理录制(record&replay,单独立项)与 OpenAPI/Swagger/curl 导入生成规则骨架为二期优先**(2026-09-08 用户拍板)。

## Consequences

- 平台承担子进程管理全环:拉起/停止/探活/启动对账/孤儿回收——本域最重的工程件,缺一条两周内必翻车。
- 实例端口/base_url 是给 SUT 的**外部契约**,一旦分发改动成本高——端口编辑仅停止态可用即由此来。
- 新依赖 jsonpath-ng(条件匹配)、jinja2(模板响应);新表 mock_instances / mock_rules / mock_hits;
  命中记录每实例滚动 1000 条、体截断 64KB(常量,可配置化 DEFER)。
- 无鉴权 mock 端口构成 LAN 暴露面:内网单机已接受;平台外露部署前需单独收口(DEFER)。
- 二期遗留扩展位:菜单「接口Mock」组预留多协议子项(gRPC 等),当前不做、仅命名占位。
